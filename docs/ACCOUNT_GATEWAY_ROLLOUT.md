# No-domain account gateway — rollout checklist

This change fixes the unsafe direct client-IP dependency in `account-auth`. Account signup/login/recovery/rotation now travel Android → Cloudflare Worker (your free `*.workers.dev` URL) → Supabase. The Worker authenticates itself to `account-auth` with a private shared secret and supplies the canonical `CF-Connecting-IP` from Cloudflare's inbound request, **not a header supplied by the Android client**. The public Supabase Edge URL remains reachable but cannot operate without the matching shared secret.

**Deployment is not done by committing this code. Keep `ACCOUNT_AUTH_ENABLED=false` until the full checks pass.** No domain purchase is needed. The gateway URL is a public identifier, not a password. Do not place the shared secret in Android, GitHub build variables, a message, logs or code.

1. Create a free Cloudflare account, Workers & Pages → Create Worker. Use `gateway/account-auth-worker.mjs` as the script (or deploy from this folder with Wrangler and `gateway/wrangler.toml`). Keep the provided `https://<worker>.<account>.workers.dev` hostname. Install three Cloudflare Worker bindings: `SUPABASE_URL=https://vjjvfshpzihbrdakbzct.supabase.co`, `SUPABASE_ANON_KEY` = your project's public anon/publishable key, and `ACCOUNT_AUTH_GATEWAY_SECRET` = a *new* 64-character random hexadecimal secret, stored as a Cloudflare **Secret**. Do not reuse `MAINTENANCE_SECRET`, `ACCOUNT_RECOVERY_PEPPER`, or client signing secrets. Never log auth request/response bodies or headers.
2. In Supabase Edge Function Secrets, set `ACCOUNT_AUTH_GATEWAY_SECRET` to the identical private value, `ACCOUNT_AUTH_IP_HEADER=x-trusted-account-ip`, keep `ACCOUNT_RECOVERY_PEPPER` stable, and keep `ACCOUNT_AUTH_ENABLED=false`. Deploy the updated `account-auth` Edge Function **from this branch**, including its `_shared` source, only after checking migration compatibility. Do not redeploy the previous ungated adapter or change other functions.
3. Verify the worker accepts only POST `/account-auth`, fails if `CF-Connecting-IP` is absent, overwrites caller-provided `x-trusted-account-ip` and `x-account-gateway-secret`, and forwards the active session Bearer only when present. Verify direct Supabase calls with spoofed or missing shared secret return 503. Check gateway requests from two different networks are limited separately, and requests without or with a malformed IP fail. **Worker unit tests cannot prove Cloudflare's live header provenance; inspect deployed request behavior**. Rotate the shared secret if exposed.
4. Before enabling registration, confirm Supabase migration 012 and the stored RPCs/trigger match the code; do not reset existing data, blindly replay older SQL, or fabricate migration history. Review Supabase Auth password/email settings, outgoing email hooks, and Admin `createUser` compatibility with the server-generated `@calculator-messenger.invalid` aliases on disposable test identities. Disable public self-signup while retaining Admin createUser/email-password sign-in. Test signup race, rate limiting, invalid credentials, recovery and revoked-session RLS on staging. Confirm no synthetic email is sent.
5. After owner approval and all live spoof/security tests, set `ACCOUNT_AUTH_ENABLED=true`. In GitHub Actions repository **Variables**, add `ACCOUNT_AUTH_GATEWAY_URL=https://<worker>.<account>.workers.dev/account-auth`. Keep this as a non-secret *public* variable. Build `android-debug.yml` in **connected** mode from the changed branch. Production connected builds without this URL now fail at config validation rather than silently shipping nonfunctional auth.
6. Install on two disposable Android devices and verify registration, login, code storage, PIN+biometric/device gates, logout, recovery, calls and push. Do not enable the paused `calculator-maintenance` or `calculator-push` schedules until separately verified.

Live infrastructure (Cloudflare Worker, private secrets, Supabase flag, Auth provider controls) still requires owner-side configuration. Unit and CI results do not imply live account creation, true spoof resistance or a working production APK. Ensure the provider URL has its exact `/account-auth` path; never use the Worker as an open arbitrary proxy.

Code paths: `gateway/account-auth-worker.mjs`, `supabase/functions/account-auth/index.ts`, `lib/core/services/account_gateway.dart`, `scripts/prepare-client-config.py`.

Reference: https://developers.cloudflare.com/fundamentals/reference/http-headers/ and https://developers.cloudflare.com/workers/examples/conditional-response/
